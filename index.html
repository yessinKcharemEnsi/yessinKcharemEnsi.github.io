~/approach

Most performance problems arrive with a theory already attached. The theory is usually wrong, and acting on it costs a week.

So I measure first. On the platform I work on now, that meant Prometheus metrics on every service, Grafana dashboards that make degradation visible rather than inferable, and Elastic APM traces that follow one request the whole way through. When the numbers looked bad I went a layer down — Java Flight Recorder for JVM behaviour, pg_stat_statements for the queries and connections actually under strain. The bottleneck was never quite where anyone predicted. Fixing the real one cut response time in half.

The same instinct shapes how I build. The ingestion framework below is deliberately boring: a coordinator splits the work, identical pods do the same job in parallel, validation rules live in configuration rather than code, and rejected records are quarantined instead of dropped. Nothing clever. It scales by adding pods, and when it misbehaves the metrics already say why.
